# DevCleaner — пошаговый план

> Правило для Codex: **выполни ровно один следующий утверждённый шаг, остановись, объясни diff и попроси review**. Не реализуй весь roadmap одним запросом.

## Уже есть (проверено владельцем на Mac)
- [x] Минимальное SwiftUI-приложение в одном окне.
- [x] Показ общего, занятого и свободного места.
- [x] Сканирование Xcode / Gradle / Android и базовые кнопки Finder.
- [x] Очистка DerivedData с подтверждением.
- [x] Журнал операций.
- [x] Раскрывающиеся категории и просмотр размеров вложенных папок (реализовано **локально**, актуальная копия кода на Mac может отличаться от исходного архива).

## Этап 0 — закрепить исходное состояние
- [ ] **0.1.** Добавить `AGENTS.md`, `ARCHITECTURE.md`, `ROADMAP.md` в **корень**, не изменяя Swift-код.
- [ ] **0.2.** Сверить фактические Swift-файлы с архитектурой, особенно `StorageChild`, `scanChildren`, `loadChildren`, отображение `DisclosureGroup`. Обновить документацию, только если факты отличаются. Никакой перестройки.
- [ ] **0.3.** Проверить `swift build` и `swift run` на Mac, зафиксировать результат. Ничего не удалять для проверки.

## Этап 1 — понятный интерфейс анализа (только read-only)
- [ ] **1.1.** Добавить визуальные полосы размера у вложенных папок. Размер сравнивать с объёмом выбранной категории; число показывать рядом. Изменение преимущественно `DashboardView.swift`.
- [ ] **1.2.** Для пустой/недоступной категории показывать различимые состояния: пусто, не найдено, ошибка прав. Не скрывать ошибку под «нет элементов».
- [ ] **1.3.** Добавить «Обновить категорию»: переизмерять только один раздел, явно сбрасывая его кэш. Защититься от устаревших фоновых результатов при повторном сканировании.
- [ ] **1.4.** Улучшить визуальную иерархию (отступы, заголовки, тёмная/светлая тема) без смены базовых экранов.

## Этап 2 — React Native проекты (сначала только просмотр)
- [ ] **2.1.** Добавить категорию `React Native Projects` с поиском в `~/Documents` на **ограниченную глубину**. Узнавать RN-проект по `package.json` и зависимостям React Native/Expo. Не обходить весь диск.
- [ ] **2.2.** Показывать найденные проекты и размер каждого, с открытием в Finder.
- [ ] **2.3.** По раскрытию проекта считать `node_modules`, `android/build`, `android/app/build`, `ios/Pods`, `.git` и остальные каталоги. Не суммировать вложенные друг в друга значения дважды.
- [ ] **2.4.** Добавить пояснения: что является кэшем, что — зависимостями, что — данными проекта. **Никакого удаления на этом этапе.**

## Этап 3 — безопасная выборочная очистка
- [ ] **3.1.** Согласовать с владельцем таблицу допустимых путей и риск каждой операции; без реализации удаления.
- [ ] **3.2.** Реализовать в `CleanupService` только **одну** утверждённую операцию Gradle (например, `~/.gradle/caches`) с проверками пути, каталога, симлинков, активных сборок и чётким подтверждением. Не удалять `~/.gradle` целиком.
- [ ] **3.3.** Добавить отдельный UI для её запуска и отображение полного/частичного результата. Подтверждение должно называть точный путь и последствия.
- [ ] **3.4.** Обновлять размеры после завершения; корректно обрабатывать ошибки и отказ пользователя.
- [ ] **3.5.** Только после обсуждения рассмотреть дополнительные операции; не включать очистку SDK, симуляторов, AVD, `.git`, исходников или глобальных macOS-кэшей.

## Этап 4 — удобство и качество
- [ ] **4.1.** Показать оценку *потенциально освобождаемого* места, суммируя только разрешённые независимые категории, без двойного подсчёта.
- [ ] **4.2.** Добавить удобное копирование путей, ошибок и логов.
- [ ] **4.3.** Улучшить выполнение долгих сканирований: индикаторы на уровне категории, отмена/игнорирование устаревших результатов, никаких подвисаний UI.
- [ ] **4.4.** Проверить сборку `.app` (`./scripts/build-app.sh`), открытие Finder и работу после перезапуска.
- [ ] **4.5.** Освежить README и архитектурную документацию по факту.

## Отложено — НЕ делать сейчас
- Тесты, test target, XCTest, CI — добавим отдельным этапом позже.
- Автоматическая и фоновая очистка, расписания.
- Многослойная архитектура, сторонние библиотеки, DI.
- Сканирование всего диска / доступ администратора / распространение через App Store.
- Удаление симуляторов, Android SDK, AVD, `.git` и пользовательских данных.

## Формат одной задачи для агента

> Прочитай `AGENTS.md`, `ARCHITECTURE.md` и `ROADMAP.md`. Выполни **только шаг X.Y**. До правок перечисли файлы и минимальный план. Сохрани простую структуру, не добавляй зависимости и тесты. После — покажи изменённые файлы, ключевые фрагменты diff, объясни новые конструкции Swift и отличие от React/TypeScript, укажи выполненную проверку и шаги ручной проверки. Остановись и дождись review.

## Правила отметок
- `- [ ]` — ещё не реализовано/не проверено.
- `- [x]` — реализовано и фактически проверено.
- Если проверка не удалась — пункт не закрывать, описать причину.
- Не отмечать шаги автоматически лишь потому, что код написан.
